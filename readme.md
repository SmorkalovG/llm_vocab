# Spanish Vocabulary Extractor — документация

## Назначение

Одностраничное приложение для извлечения испанской лексики из произвольного текста с помощью LLM. Выделяет слова и устойчивые выражения, определяет словарную форму, русский перевод и примерный уровень CEFR. Позволяет фильтровать, редактировать и выбирать лексемы, затем экспортировать их в TSV для Anki.

Работает полностью в браузере, без backend, базы данных и постоянного хранения состояния. Внешние запросы выполняются только к LLM API.

## Структура проекта

- `index.html` — интерфейс и CSS.
- `app.js` — конфигурация, промпт, запросы API, обработка данных, таблица и экспорт.

Никаких зависимостей, сборки или дополнительных библиотек.

## Ключевые точки изменения (`app.js`)

- Адрес API, ключ и модель задаются в сворачиваемом блоке «Настройки» вверху страницы (`index.html`). По умолчанию: `http://localhost:8081`, пустой ключ, `local-model`. К адресу автоматически добавляется `/v1/chat/completions`; при заполненном ключе отправляется заголовок `Authorization: Bearer …`. Настройки не сохраняются между перезагрузками.
- `MAX_TEXT_LENGTH`, `MAX_IMAGE_BYTES`, `REQUEST_TIMEOUT_MS` — ограничения текста, изображений и времени запросов.
- `SYSTEM_PROMPT` — правила лингвистического разбора. Главная точка настройки качества результата.
- `analyze()` — формирование запроса, вызов API, обработка ошибок.
- `decodeModelResponse()` — разбор JSON, валидация и дедупликация.
- `visibleRows()` — логика фильтрации.
- `render()` — отображение таблицы и редактирование данных.
- `downloadTsv()` — экспорт в Anki.

## Контракт данных

LLM возвращает JSON-массив объектов:

```json
{
  "lexema": "me di cuenta",
  "orig": "darse cuenta",
  "russian": "осознавать",
  "rate": "B1",
  "ext": false
}
```

`rate` принимает A1–C2 или `null`; `ext` — строго boolean. Все остальные поля — непустые строки.

Внутри приложения каждая строка дополнительно содержит `id` и `selected`.

## Инварианты

1. Источник истины — массив `rows` в памяти JavaScript. DOM не хранит независимое состояние словаря.
2. Фильтрация меняет только видимость строк, но не удаляет данные и не сбрасывает `selected`.
3. Все новые строки имеют `selected: false`. Успешный повторный анализ полностью заменяет результаты; ошибка оставляет предыдущие.
4. Дубликаты удаляются по сочетанию `orig + russian` без учёта регистра.
5. Значения `rate: null` не скрываются CEFR-фильтром.
6. TSV содержит только отмеченные строки: `orig<TAB>russian`, без заголовка, UTF-8 с BOM. Экспорт учитывает даже скрытые фильтром строки.
7. Исходный текст и результаты не сохраняются между перезагрузками.
8. Данные LLM считаются недоверенными: проверяются перед использованием и выводятся как текст, не HTML.

## Запуск и ограничения

Открыть `index.html` в браузере. API должен поддерживать CORS, в том числе запросы со страницы `file://` (origin `null`).

Для работы необходим доступный OpenAI-compatible endpoint по адресу `/chat/completions`. Модель должна возвращать JSON в `choices[0].message.content`.

Поддерживаются текст, `.txt` и одно изображение (PNG, JPEG, WebP, GIF, до 20 МБ). Выбранное изображение можно просмотреть, заменить или удалить; текст и изображение можно отправить вместе. Загрузка TXT заменяет текст, сохраняя выбранное изображение.

Изображение читается локально через `FileReader` и передаётся в `messages[].content` пользовательского сообщения как `{ "type": "image_url", "image_url": { "url": "data:image/…;base64,…" } }` вместе с частью `type: "text"`. Это [формат Chat Completions для изображений](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat). Системный промпт и обработка результатов остаются общими с текстовым вводом. Нужна модель с поддержкой изображений. При отправке только текста сохраняется строковый формат `content`.

Текст, изображение и результаты хранятся только в памяти страницы. Видео пока не поддерживается.
